验收以固定构建的实际行为为准，并保留源码和手册冲突记录。

## 2. “一致”的验收合同 / Observable contract

完整目标需要可兼容调用的 CLI 层及库能力。只有 typed API 返回相同的少数字段，不足以对齐 ipmitool。
每个矩阵项必须继续展开为 `入口 × 子命令 × 参数/默认值 × 接口/构建 × 权限 × 设备能力 × 成功/失败路径` 的叶用例。
矩阵中的功能组是审查和跟踪单位，不是假称已经枚举所有参数取值或完成穷尽测试。

每个叶用例同时检查以下可观察面：

1. **调用与输出**：参数顺序、别名、默认命令、大小写/前缀处理、帮助、stdout/stderr 分流、退出码、CSV、数值精度、文本、排序、空值、错误及警告。
2. **通信**：发现请求、权限协商、地址/LUN/桥接、命令与 payload、分块、完成码、重试次数/间隔、超时、重复响应处理、关闭会话及取消行为。
3. **副作用**：BMC 状态改变、是否发送额外请求、生成/覆盖的文件、终端模式、信号处理、日志、后台进程和退出后的资源。
4. **平台行为**：该构建真实提供的接口、默认接口、选项集、依赖缺失和设备不可用时的错误；一个平台的结果不替代其他平台。

在固定 `LC_ALL=C`、`TZ=UTC`、受控当前时间、固定数据文件及相同初始设备状态下比较输出。
另设非默认时区、`-Z`、locale、环境变量和 TTY/非 TTY 用例，不能用固定环境掩盖这些功能差异。
优先逐字节比较 stdout/stderr/导出文件；协议中的 nonce、session ID、随机 IV 等只能做明确字段的关联校验，
不得删除整个报文或输出行。耗时比较使用有依据的容差，同时精确比较重试/等待状态机，不能要求两次运行的墙钟时间完全相同。

任何允许的归一化、程序名称/版本显示差别或故意保留的保护都须单独列出并由用户决定。
只要有一项可观察差异被保留，就只能声明具体范围的兼容性，不能声明“无缺失、无差异”。
ipmitool 中不可复现的未定义行为、崩溃或对环境偶然依赖的表现要作为阻塞项记录，不能承诺复制内存错误。
有限测试也不能证明所有未知硬件、所有输入的绝对等价；最终声明必须限定参考提交、构建、环境和已验收场景。

## 5. 平台、硬件与权限资源 / Required resources

| 验证环境 | 要解决的问题 | 当前状态 |
|---|---|---|
| Ubuntu 24.04/macOS 15 native | 重建参考 profile 与 MoonBit；覆盖 CLI、lan/lanplus、加密库与 readline 差异 | 首个四接口 profile 已加入两个 CI 平台；更广 profile 未冻结；macOS 不能验证本地 Linux 驱动 |

远程权限至少覆盖 NULL/匿名情形及 CALLBACK、USER、OPERATOR、ADMINISTRATOR、各 channel/user/payload 限制和拒绝路径。
这是对参考能力的盘点，不表示本轮允许匿名或高权限访问。各命令的最低权限须依据参考请求和目标策略实测，不能一概假定读取都允许 User、写入都只需 Operator。
本地接口取决于 OS 设备节点、组、ACL 或 D-Bus 策略，不等同于远程 Administrator；不无条件使用 root。
固件和 OEM 还可能要求厂商角色、物理跳线或特定固件状态，必须单独登记。

## 6. 必须审核的行为冲突 / Conflicts

以下是当前实现/既有安全约束与完全一致目标之间的具体冲突，不是本轮修改安全行为的许可。
如用户选择保留差异，矩阵记为 `DIVERGENT`，全量一致目标仍未满足；不能从分母里移除。

[统一裁决汇总](PARITY_DECISIONS.md)链接 GUID、精度、部分输出、套件列表及安全实测证据和建议。CLI 决策仍未作出，大计数 API 精度按用户指示保持现状。

| ID | 参考行为或待测分支 | 当前差异与需要的决定 |
|---|---|---|
| K01 | LAN 1.5、NONE/较弱认证、lanplus 套件选择与回退、Kg、NULL 用户/密码 | 当前仅 suite 17、非空凭据、无降级。决定是否允许实现参考兼容策略；弱模式只能在隔离合成环境先取证 |
| K02 | 默认 Administrator，`-L`/`+` lookup、桥接可能强制高权限 | 当前固定 User/role 0x02；既有 ipmitool 对照 role 为 0x12。默认值、权限变化都要测试和审核 |
| K03 | 参考对部分已认证畸形 IPMI 字段更宽容 | 当前拒绝错误 responder、netfn/LUN、checksum；已有 24 项对照。决定保留保护还是按参考接受；不能把“更严格”判成一致 |
| K04 | 自动重试、命令专有超时、丢弃后继续等待、关闭请求 | 当前逐次时限、单在途、失败关闭、无重试；FRU/SEL 有总限额/整体时限。复制重试可能重复执行有状态命令；必须验证中途失败和未知执行结果 |
| K05 | raw/I2C、账户/LAN/电源/SEL/FRU/固件等可改变状态 | 当前只读 allowlist。未来能力与执行权限要区分；额外确认提示、默认拒绝或增加开关都会改变 CLI 行为，不能静默加入后宣称严格一致 |
| K06 | `-P`/环境/文件/交互密码、`-v` 报文日志、shell history | 当前不暴露凭据/报文；需要决定日志与凭据暴露兼容边界。只用合成秘密形成测试样本；真实凭据不进入报告 |

| K08 | 完整读取、格式/编码/OEM 解释、导出文件、动态仓库 | 当前部分 raw 保留、ASCII 子集、有界枚举、非原子读取及失败无部分输出；必须比较参考的错误/部分结果语义，不能删除差异字段 |

## 7. 逐项验收与完成条件 / Acceptance

矩阵每个叶用例的报告必须包含：稳定 ID、引用源码分支、两端完整提交/构建 profile、命令/输入、fixture 版本和初始状态、
权限、stdout/stderr/退出码、脱敏通信轨迹、操作前后状态、差异、时间及证据链接。
两客户端从相同且分别重置的初始状态运行；对写入、计数器、时间和事件，不允许前一个客户端污染后一个客户端的输入。
响应/故障注入由独立 fixture 定义，不能因识别客户端而调整数据。失败应保存最小复现并对照真实参考执行，不只比较自写预期。

状态使用 `NOT_IMPLEMENTED`、`PARTIAL`、`UNVERIFIED`、`BLOCKED_ENV`、`BLOCKED_DECISION`、`DIVERGENT`、`PASS`。
“参考也不支持”的具体构建组合可记录 `REFERENCE_UNAVAILABLE` 并对齐其错误，但同一功能在其他受支持组合上的要求仍存在。
没有设备的功能记阻塞，不记 PASS/N/A。一个功能组仅在所有叶用例和依赖完成后才能 PASS；代码存在、帮助列出、单次模拟通过均不足以通过整组。

全量完成须同时满足：

- 源码入口、选项、子命令分支、配置表、接口条件和配套工具均有用例映射，新增发现不得遗漏；没有未展开或未解释的条目。
- 已审核的完整平台/接口/设备矩阵均执行；没有未解决的缺失、差异、环境或决策阻塞，也没有用缩小范围代替补齐功能。
- 所有确定性可观察行为匹配；随机性、时间容差和身份显示的处理有明确审核结果，任何保留差异在声明中直说。
- 每个实际硬件结论有明确型号/固件/权限/接口证据；不能由一个 BMC 推断所有 BMC，也不将模拟测试宣传为硬件验证。
- 对认证、FFI/驱动、文件、长连接和固件路径进行针对性审查；审查通过不自动等于外部安全审计或发布许可。

审核时需要确认：1.8.19 固定基线与全构建并集；CLI/库/ipmievd/配套脚本的交付边界；K01–K10 的处理方向；
可获得的平台/设备资源。P1 及独立只读实现已获准进行，详见[进度及建议](IPMITOOL_REFERENCE.md)。当前有状态开发、真实设备操作和发布限制继续有效。

继续参考证据及独立只读功能开发；K01–K10 未裁决的实现改动保持阻塞。
不建议用删减旧接口、弱认证或 OEM 功能来降低验收范围；若坚持完全一致，这些功能和已知差异必须实际处理。
对潜在内存错误、真实秘密暴露及不可控副作用，不建议直接复制缺陷；保持阻塞并提交具体可复现事实供审核，不能暗改目标。
